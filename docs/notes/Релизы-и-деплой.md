# Релизы и деплой

## Порядок
1. Работа в ветке сессии → PR в `main` → CI зелёный → мерж (Claude мержит сам с разрешения владельца).
2. Релиз: **миграции → Edge Functions → фронтенд**; каждый шаг обратно совместим.

## GitHub Actions
- `ci.yml` — на каждый PR: frontend (lint, test, build), edge-functions (`deno check`), e2e (Playwright).
- `deploy-functions.yml` — деплой Edge Functions при мерже в `main` (секрет `SUPABASE_ACCESS_TOKEN`).
- `deploy-pages.yml` — сборка и деплой Mini App на GitHub Pages при мерже в `main` (кроме изменений
  только в `docs/` и `.claude/`).
- Cloudflare Pages собирает превью для каждого PR.

## Проверки перед PR
```bash
npm test && npm run lint && npm run build && npm run test:e2e && git diff --check
deno check --node-modules-dir=none supabase/functions/<fn>/index.ts   # для каждой функции
```
Плюс `/code-review`, для бэкенда и БД — `/security-review`.

## Выбор модели для задачи
Haiku/low — тексты и документация; Sonnet/medium — вёрстка, экраны, разбор логов;
Opus/high — БД, бэкенд, безопасность; Opus/xhigh — сложная конкурентность и безопасность.
