# Mini App

React + Vite + TypeScript. Открывается как `https://t.me/flocklyappbot/app`.

## Структура `src/`
- `App.tsx` — маршрутизация и каркас; экраны — `src/screens/`:
  `Home`, `CreateEvent`, `Created`, `ParticipantEvent` (голосование), `Result`, `Manage`, `MyEvents`,
  `PublicMeetings` (открытые встречи), `PublicPreviewScreen`, `NotificationSettingsScreen`,
  `AdminStatsScreen` (только администратор), `SystemScreens` (ошибки, «сессия устарела», вне Telegram).
  `PlacesScreen` («Куда сходить», вкладка «Места», `/places`; старый путь `/map` ведёт туда же),
  `AdminVenuesScreen` (`/admin/venues`, только администратор).
- Нижнее меню — `src/BottomNavigation.tsx`, пункты — `bottomNavigationItems` в `src/navigation.ts`.
- `src/ui/` — общие компоненты; `src/app-hooks.ts` — хуки; `src/share.ts` — отправка карточки в чат;
  `src/api.ts` — клиент [API](API.md); `src/meeting-links.ts` — ссылки на встречу.
- Стили — `design-tokens.css` и `theme-sunset.css`, см. [Дизайн «Закат»](Дизайн-Закат.md).

## Язык и настройки
- Шестерёнка в правом верхнем углу главной (вместо переключателя темы) открывает «Настройки» (`/settings`,
  `SettingsScreen`): язык «Как в Telegram / Русский / English», тема «Как в Telegram / Светлая / Тёмная»,
  ниже — уведомления бота (`NotificationSettingsPanel`).
- Тексты — в коде на русском, обёрнуты в `t("…")` (`src/i18n.ts`, ключ — сам русский текст, как в gettext);
  английские — `src/i18n-en.ts`, подстановки `{name}`, множественное число — `plural()` с английскими формами
  по русской «one»-форме. Нет перевода — показывается русский. Новый текст в интерфейсе — сразу добавить
  английский: тест `tests/i18n.test.ts` проверяет, что у каждой русской строки есть перевод и что в JSX нет
  русского текста без `t()`.
- Язык по умолчанию — по `language_code` Telegram: русский для ru/be/uk/kk/ky/uz/tg/tk/hy/az, иначе английский;
  выбор хранится в `localStorage` (`flockly.language`). Даты — `locale()` (ru-RU / en-GB).
- Сообщения сервера (ошибки), названия категорий и городов приходят по-русски и переводятся на клиенте по тому
  же словарю. Каждый запрос несёт заголовок `x-flockly-language`: даты-сводки сервера, превью и карточки
  «Поделиться» приходят уже на нужном языке.
- Выбор языка сохраняется и на сервере (`PUT /me/language`, по очереди — `src/language-preference.ts`) — для
  бота и уведомлений. После входа `languageSync`: если выбор этого устройства уже дошёл до сервера
  (`flockly.language.synced`), главный — сервер (там может быть более новый выбор с другого устройства); выбор,
  который не дошёл (сделан до шага 2 или сохранение не удалось), отправляется. Ошибка сохранения не мешает работе.

## Город
В «Открытых встречах» — плашка города. Пока открыт один город — просто подпись; когда их больше —
выпадающий список (`PUT /me/city`). Выбор — это «ваш город»: от него зависят лента и город новых встреч.

## Категории и поиск
- Мастер создания, шаг 1: необязательная категория (список — `GET /categories`; нет списка — встреча создаётся без
  категории). Категория уходит в запрос только если выбрана — ключ идемпотентности прежних черновиков не меняется.
- «Открытые встречи»: поиск по названию (пауза 350 мс, Enter — сразу) и плашки категорий «Все / …»; при смене
  фильтра старая выдача приглушается до ответа, ошибка новой выдачи её очищает; «Ничего не нашлось» — со сбросом.
- Значок категории — на карточке ленты, в превью открытой встречи, на экранах участника и управления
  (`CategoryBadge`, поле `category` в объекте встречи), плашка — `CategoryChip`.
- В «Управлении» категория меняется сразу по нажатию на плашку (действие `set_category`; повторное нажатие
  снимает категорию). Отдельно от «Сохранить описание»: смена категории никого не уведомляет.

## Места (этап 2.3)
- Вкладка «Места» → «Куда сходить»: опубликованные места города с поиском и плашками категорий, «Рекомендуем»
  сверху. Карточка: категория, адрес, уровень цен, часы работы, «Создать встречу» и ссылка «Сайт» или
  «На карте» (OSM). Карта мест — этап 4.
- «Создать встречу» с карточки открывает мастер с этим местом в списке вариантов и категорией места
  (`startMeetingAtVenue` в `src/venues.ts`; мастер забирает место один раз).
- Мастер, шаг 3: «Подборка мест» (`VenuePicker` в `src/ui/Venues.tsx`) — места категории встречи по общему
  бюджету (пауза 400 мс после ввода), по 5 с «Ещё места»; нажатие добавляет вариант места (название, адрес,
  бюджет по уровню цен: 15/35/60 BYN, без уровня — общий бюджет). Пока в городе нет мест, подборки не видно.
- «Места» → «Список / Карта». Карта — MapLibre (`src/ui/VenueMap.tsx`, грузится только при открытии: ~290 КБ gzip;
  worker собирается Vite через `?worker&url`) и тайлы OpenFreeMap (без ключа; светлый стиль positron, тёмный —
  dark, при ошибке тёмного — светлый). Места — кластеры, «Рекомендуем» — тёплым цветом, открытые встречи —
  розовые точки (только с местом из каталога). Нажатие — карточка внизу: место («Создать встречу») или встреча
  («Подробнее»). Пока карта открыта, свайп Telegram «вниз — закрыть» отключён (`holdVerticalSwipes`, Bot API 7.7).
  Без WebGL — подсказка смотреть списком.
- Атрибуция «© участники OpenStreetMap» — под списком, если в нём есть места из OSM (требование ODbL).
- Администратору: «Каталог мест» на главной — загрузка из OpenStreetMap по категориям, ручное добавление,
  вкладки «Новые / Опубликованы / Скрыты», категория, цены, «Рекомендуем», «Опубликовать все на экране».
- Загрузку из OpenStreetMap делает само приложение администратора (`src/osm-import.ts`): публичные серверы
  Overpass не обслуживают облако Supabase (2026-10-15: 5xx, таймауты, «only white-listed»). Приложение по очереди
  спрашивает серверы из ответа `/admin/venues`, отправляет найденное на сервер; при ошибке пишет, что ответил каждый.
  Хосты Overpass разрешены в `csp.ts`.

## Безопасность (этап 2.4)
- Первый вход в «Открытые встречи» — окно «Правила открытых встреч» (`CommunityRulesDialog`, тексты —
  `src/moderation.ts`); внизу ленты — ссылки «Правила» (`/rules`) и «Заблокированные» (`/blocked`).
- «Пожаловаться» / «Заблокировать» (`SafetyActions`): в превью открытой встречи и у участника открытой встречи —
  на встречу и организатора; у организатора — на участника (раскрытый ответ в «Управлении») и автора заявки.
  Диалоги рендерятся в `<body>` через портал: стеклянные панели с `backdrop-filter` обрезали бы оверлей.
- Администратору: «Жалобы» на главной (`/admin/reports`) — вкладки «Новые / Решённые / Отклонённые», действия
  «Скрыть встречу / Вернуть в ленту», «Ограничить / Снять ограничение», «Решено», «Отклонить».
- Организатор скрытой встречи видит в «Управлении» пометку, что встреча убрана из ленты.

## Ссылки и параметры запуска
- Встреча: `https://t.me/<bot>/<app>?startapp=event_<id>`.
- Кнопки бота открывают экраны через `?screen=create` и `?screen=my-events`.
- Переходы из уведомлений помечаются источником `ntf_<id>` (для аналитики).
- `startapp=reports` — уведомление о жалобе, открывает «Жалобы» (только администратору).

## Поведение
- `initData` живёт 1 час; при 401 показывается экран «Сессия Telegram устарела → Открыть заново».
- Создание встречи идемпотентно: ключ `clientRequestId` хранится на черновик и переживает перезагрузку.
- Первое действие, которому нужны уведомления, запрашивает `requestWriteAccess()`.

## Локальный запуск без Telegram
```bash
VITE_USE_MOCK_TELEGRAM=true VITE_USE_MOCK_API=true npx vite
```
Проверки: `npm test`, `npm run lint`, `npm run build`, `npm run test:e2e` — см. [Релизы и деплой](Релизы-и-деплой.md).
