# База данных

Supabase PostgreSQL, проект `qesuhhhiswwrfvfisfkp`. Миграции — `supabase/migrations/`.

## Таблицы
- Встречи: `events`, `time_options`, `place_options`, `participants`, `availability_votes`, `place_votes`,
  `join_requests`, `event_creation_requests` (идемпотентность создания).
- Города: `cities` (`id`-слаг, `name`, `timezone`, `is_active`, `sort_order`). Активен только Минск;
  Брест, Витебск, Гомель, Гродно, Могилёв — выключены до этапа 4. Города не удаляются, только выключаются.
- Пользователи: `users` (в т. ч. `can_message`, `city_id` — выбранный город, `null` = Минск), `notification_preferences`.
- У встречи `events.city_id` (not null). Если город не передан, триггер `events_set_city_from_owner`
  берёт активный город организатора, иначе Минск; явно переданный город сохраняется.
- Уведомления: `notification_outbox`, `event_notification_state` — см. [Уведомления](Уведомления.md).
- Группы: `event_group_chats`, `group_links`, `group_message_outbox`.
- Аналитика: `analytics_events`.

## Задачи pg_cron
`enqueue-due-notifications`, `notifications-worker` (каждую минуту), `archive-completed-events-hourly`,
`purge-notification-outbox-daily`, `purge-event-creation-requests-daily`, `purge-group-data-daily`,
`purge-analytics-events-daily`.

## Правила
- Новые таблицы не дают `service_role` прав на данные по умолчанию: для чтения из функции нужен явный
  `grant select on table public.<t> to service_role;` (урок 2026-10-14: без него упала лента после релиза городов;
  тогда же нашлось, что `place_votes` тоже не читалась). Проверка — `tests/service-role-grants.test.ts`.
- Все таблицы с RLS, без прав у `anon`/`authenticated`. Изменения — атомарные RPC `security definer`
  с `set search_path = pg_catalog, public`, доступ только у `service_role`.
- Миграции продакшена — **только** через Supabase-коннектор (`apply_migration`). Запрещены
  `supabase db push/reset`, `migration repair/pull/list`, `--include-all`, прямые подключения.
- После применения — переименовать файл под версию Supabase и сверить текст со
  `supabase_migrations.schema_migrations.statements`.
- Баг коннектора: зависает на `drop ...`, на `raise` + `delete` в одном теле функции, на двух `delete` в одном
  теле. Обходы — `create or replace trigger`, каждый `delete` в отдельной функции без `raise`.
- Локальная проверка: Postgres 16 с заглушками `auth`, `vault`, `cron`, `extensions`, все миграции по порядку,
  сценарии с параллельными запросами.
